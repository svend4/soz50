## 1. Для кого этот документ

Этот документ адресован всем, кто работает с большими массивами информации в профессиональных целях:

| Группа | Типичные задачи |
|--------|----------------|
| **Журналисты** | Расследования, OSINT, архивы источников, факт-чекинг |
| **Правозащитники** | Ведение дел, сбор доказательств, мониторинг нарушений |
| **Учёные / исследователи** | Литературный обзор, данные, воспроизводимость |
| **Социальные работники** | Карточки клиентов, законодательство, прецеденты |
| **Юридические консультанты** | Судебная практика, нормативная база, шаблоны |
| **НКО / активисты** | Документирование событий, коммуникация, отчётность |

**Ключевая идея:** несмотря на разные предметные области, методологические проблемы одинаковы — как найти, организовать, сохранить и извлечь нужную информацию из тысяч документов.

## 2. Фундаментальные принципы

### 2.1 Принцип LATCH (Ричард Солоу / Ричард Вурман)

Любую информацию можно организовать по пяти основаниям:

| Буква | Принцип | Пример |
|-------|---------|--------|
| **L** | Location (место) | Дела по городам, законы по федеральным землям |
| **A** | Alphabet (алфавит) | Индекс терминов, именной указатель |
| **T** | Time (время) | Хронология событий, история изменений законов |
| **C** | Category (категория) | SGB II, SGB XII, AsylbLG — тематические разделы |
| **H** | Hierarchy (иерархия) | Общее → конкретное, как в этой базе знаний |

**Рекомендация:** комбинируй принципы. Эта база знаний использует H+C как основу, T+A для навигации.

### 2.2 Принцип единого источника правды (Single Source of Truth)

- Одна информация — одно место хранения
- Везде, где нужна ссылка — ставь ссылку, не копируй текст
- Копирование создаёт расхождения при обновлении

### 2.3 Принцип наименьших усилий для извлечения

Система хороша не тем, как легко в неё вложить информацию, а тем, как легко её оттуда достать.

> "A system is only as good as its worst search."

### 2.4 Принцип последовательности (Consistency)

- Одинаковые названия для одинаковых понятий
- Одинаковый формат дат (ISO 8601: `YYYY-MM-DD`)
- Одинаковая структура метаданных
- Контролируемый словарь тегов

## 3. Архитектура информации

### 3.1 Иерархические структуры (деревья)

**Когда использовать:** предметная область хорошо известна заранее, документы чётко классифицируются.

```
Корень
├── Категория A
│   ├── Подкатегория A1
│   │   ├── Документ 1
│   │   └── Документ 2
│   └── Подкатегория A2
└── Категория B
```

**Плюсы:** интуитивная навигация, легко объяснить другим
**Минусы:** документ часто "между" категориями; трудно реструктурировать

**Применение в этой базе:** `01_SOZIALRECHT/02_SGB_II/Leistungen/`

### 3.2 Плоская структура с тегами (Tags / Facets)

**Когда использовать:** документы многотематичны, нужна гибкость.

```
Все документы/
├── dokument-001.md  [теги: SGB-II, KdU, Urteil, 2025]
├── dokument-002.md  [теги: SGB-XII, Unterkunft, Widerspruch]
└── dokument-003.md  [теги: SGB-II, Sanktionen, Verfassungsrecht]
```

**Плюсы:** один документ — несколько измерений поиска
**Минусы:** теги требуют дисциплины; без контроля превращаются в хаос

**Инструменты:** Obsidian (тегирование), Zotero (коллекции + теги), Notion (база данных с полями)

### 3.3 Граф знаний (Knowledge Graph)

**Когда использовать:** важны связи между понятиями, а не только хранение документов.

```
[SGB II §22 KdU] → ссылается на → [BSG B 14 AS 50/20 R]
[BSG B 14 AS 50/20 R] → разъясняет → [Angemessenheitsgrenze]
[Angemessenheitsgrenze] → применяется в → [Fall: Familie Müller]
```

**Инструменты:** Obsidian (с плагином Graph View), Neo4j, Roam Research
**Применение:** особенно полезно для правозащитников (связь между нарушениями, акторами, жертвами) и следственной журналистики

### 3.4 Реляционные базы данных

**Когда использовать:** структурированные данные, нужны запросы и фильтрация.

```sql
SELECT * FROM cases
WHERE status = 'offen' AND rechtsgebiet = 'SGB_II'
ORDER BY eingang_datum DESC;
```

**Инструменты:** Airtable, Baserow (open source), NocoDB, PostgreSQL
**Применение:** ведение дел клиентов, отслеживание жалоб, мониторинг нарушений

## 4. Методы для журналистов

### 4.1 OSINT (Open Source Intelligence)

**Что это:** систематический сбор и анализ общедоступной информации.

**Ключевые методы:**

| Метод | Описание | Инструменты |
|-------|----------|-------------|
| **Dorking** | Расширенный поиск в Google/Bing (`site:`, `filetype:`, `inurl:`) | Google Search Operators |
| **Wayback Machine** | Архивные версии сайтов | web.archive.org |
| **Whois / IP-lookup** | Владельцы доменов, хостинг | whois.domaintools.com |
| **EXIF-данные** | Метаданные изображений (место, время, устройство) | ExifTool |
| **Реестры компаний** | Владельцы фирм, директора, связи | Bundesanzeiger, Handelsregister |
| **Социальные сети** | Публичные профили, группы | Maltego, Social Searcher |

**Рабочий процесс OSINT:**
```
1. Формулировка вопроса
2. Идентификация источников
3. Сбор данных (с сохранением скриншотов + архивных копий!)
4. Верификация (≥2 независимых источника)
5. Анализ и связи
6. Документирование методологии
```

**Критически важно:** всегда сохраняй **оригинальный URL + дату доступа + архивную копию**. Веб-страницы исчезают.

### 4.2 Управление источниками

**Принципы:**
- Каждый источник получает уникальный ID
- Храни: тип источника (анонимный, официальный, документ), достоверность, дату контакта
- Разделяй информацию от источника и атрибуцию публично

**Шаблон карточки источника:**
```yaml
---
id: SRC-2026-042
typ: Dokument | Zeuge | Offiziell | Anonym
vertrauensgrad: hoch | mittel | niedrig | unbekannt
datum_kontakt: 2026-02-27
themen: [KdU, Jobcenter, Widerspruch]
verifiziert_durch: [SRC-2026-010, SRC-2026-031]
notizen: |
  [Содержательные заметки]
vertraulichkeit: offen | vertraulich | geheim
---
```

### 4.3 Документный анализ (Large Document Review)

**Для расследований с тысячами документов:**

| Инструмент | Описание |
|-----------|----------|
| **Relativity** | Профессиональная платформа для юридических расследований |
| **Docudive** | Анализ больших массивов PDF |
| **ICIJ Datashare** | Инструмент Международного консорциума журналистов (офшорные дела) |
| **Overview** | Визуализация тематических кластеров в тысячах документов |
| **Tabula** | Извлечение таблиц из PDF |
| **OpenRefine** | Очистка и нормализация данных |

### 4.4 Верификация и факт-чекинг

**Пирамида верификации:**
```
                 ┌─────────────────────┐
                 │  Публикация          │ ← только после всего
                 └──────────┬──────────┘
                 ┌──────────▼──────────┐
                 │  Экспертная оценка  │
                 └──────────┬──────────┘
                 ┌──────────▼──────────┐
                 │  ≥2 независимых     │
                 │  подтверждения      │
                 └──────────┬──────────┘
                 ┌──────────▼──────────┐
                 │  Первичный источник │
                 └─────────────────────┘
```

## 5. Методы для правозащитников

### 5.1 Документирование нарушений (Menschenrechtsdokumentation)

**Стандарты:**

- **Стамбульский протокол** — документирование пыток
- **Беркли-протокол** — расследование цифровых доказательств открытого доступа (OSINT для прав человека)
- **ISO 27037** — сбор и хранение цифровых доказательств

**Базовые требования к каждому делу:**

```yaml
fall_id: FALL-2026-0042
datum_ereignis: 2026-01-15
datum_erfassung: 2026-02-01
ort: [Stadt, Land, Koordinaten wenn möglich]
opfer:
  - anonymisiert_id: OP-001
    geschlecht: w
    alter_ca: 34
    status: [Geflüchtete]
tater_beschreibung: |
  [Описание без идентифицирующих данных до анонимизации]
art_der_verletzung: [Inhaftierung, Körperverletzung, ...]
beweise:
  - typ: Foto | Video | Zeuge | Dokument | Medizinisch
    id: BEW-001
    aufbewahrung: verschlüsselt | sicher
    kette_beweismittel: vollständig | lückenhaft
rechtsrahmen: [EMRK Art.3, GG Art.1, ...]
status: erfasst | verifiziert | gemeldet | abgeschlossen
```

### 5.2 Цепочка хранения доказательств (Chain of Custody)

**Каждое доказательство должно иметь:**

1. **Уникальный идентификатор** (присваивается немедленно)
2. **Хеш-сумму** (MD5/SHA256) — подтверждает неизменность
3. **Журнал доступа** — кто, когда, зачем обращался к файлу
4. **Резервные копии** (минимум 3 копии в 2 местах)

```bash
# Пример: создание хеш-суммы при получении доказательства
sha256sum beweisdatei.pdf > beweisdatei.pdf.sha256
# Записать в журнал дела
```

### 5.3 Безопасное хранение чувствительных данных

**Правило трёх уровней:**

| Уровень | Данные | Хранение |
|---------|--------|---------|
| Публичный | Обобщённые отчёты, статистика | Обычные серверы |
| Конфиденциальный | Имена без персданных | Зашифрованные диски |
| Секретный | Личные данные жертв, свидетелей | Air-gapped + зашифровано |

**Инструменты:** VeraCrypt (шифрование), Signal (коммуникация), OnionShare (передача файлов), Tails OS (операционная система без следов)

### 5.4 Мониторинг и системный учёт нарушений

**Для организаций, отслеживающих паттерны:**

| Инструмент | Применение |
|-----------|-----------|
| **KoBoToolbox** | Сбор данных в поле (оффлайн-формы) |
| **Uwazi** | Специализированная платформа для прав человека |
| **ActivityInfo** | Гуманитарные организации, мониторинг |
| **ODK (Open Data Kit)** | Мобильный сбор структурированных данных |

## 6. Методы для учёных и исследователей

### 6.1 Управление литературой (Literaturverwaltung)

**Стандарт де-факто для академической работы:**

| Программа | Тип | Особенности |
|----------|-----|-------------|
| **Zotero** | Бесплатно, open source | Лучший выбор; браузерный плагин, групповые библиотеки |
| **JabRef** | Бесплатно, open source | Идеален для LaTeX/BibTeX |
| **Citavi** | Платно (Германия) | Популярен в немецких вузах |
| **Mendeley** | Бесплатно (Elsevier) | Социальная функция |
| **Endnote** | Платно | Корпоративный стандарт |

**Рабочий процесс с Zotero:**
```
1. Найти источник (Google Scholar, PubMed, BASE...)
2. Один клик → сохранить в Zotero с метаданными
3. Прикрепить PDF
4. Добавить теги и заметки
5. При написании: вставить цитату → библиография генерируется автоматически
```

### 6.2 Систематический обзор литературы (Systematic Review)

**Протокол PRISMA:**
```
Идентификация (Identification)
    ↓
Скрининг (Screening)    ← исключить по названию/аннотации
    ↓
Проверка на соответствие (Eligibility)    ← читать полный текст
    ↓
Включение (Included)    ← финальная выборка для синтеза
```

**Инструменты:** Rayyan (скрининг), Covidence (систематические обзоры), CADIMA

### 6.3 Управление данными исследования (Research Data Management)

**Принципы FAIR:**

| Буква | Принцип | Практика |
|-------|---------|----------|
| **F** | Findable (найдёмость) | DOI, метаданные, реестр данных |
| **A** | Accessible (доступность) | Открытый доступ, стабильные URL |
| **I** | Interoperable (совместимость) | Открытые форматы, стандарты |
| **R** | Reusable (повторное использование) | Лицензия CC, документация |

**Хранение данных:**
```
projekt/
├── raw/           ← оригинальные данные (только чтение!)
├── processed/     ← обработанные данные
├── analysis/      ← скрипты анализа
├── output/        ← результаты, графики
├── docs/          ← документация, кодбук
└── README.md      ← описание проекта
```

### 6.4 Воспроизводимость (Reproducibility)

**Принципы:**
- Весь анализ данных — в скриптах (R, Python, SPSS), не вручную
- Версионирование скриптов через Git
- Документирование версий программного обеспечения (`sessionInfo()` в R)
- Предрегистрация гипотез (OSF.io) перед сбором данных

## 7. Методы для социальных работников и юридических консультантов

### 7.1 Ведение дел клиентов (Fallführung)

**Структура карточки клиента:**

```yaml
---
klient_id: K-2026-042        # никогда не имя!
aufnahmedatum: 2026-01-15
zustaendigkeit: [Name Sachbearbeiter]
rechtsgebiet: SGB_II | SGB_XII | AsylbLG | Wohnen
status: aktiv | wartend | abgeschlossen | weitergeleitet
---

## Situation
[Краткое описание ситуации]

## Anliegen
[Чего хочет клиент]

## Chronologie
| Datum | Aktion | Ergebnis |
|-------|--------|---------|
| 2026-01-15 | Erstgespräch | |
| 2026-01-20 | Widerspruch eingereicht | Frist: 2026-02-20 |

## Dokumente
- [ ] Bescheid Jobcenter (erhalten: 2026-01-10)
- [ ] Widerspruch (eingereicht: 2026-01-20)
- [ ] Antwort (erwartet bis: 2026-02-20)

## Fristen
⚠️ Widerspruchsfrist: 2026-02-20

## Verweise
- Rechtsgrundlage: [§22 SGB II](../../01_SOZIALRECHT/02_SGB_II_Buergergeld/Leistungen/)
- Ähnlicher Fall: [Fall 2025-031](../../04_FALLBEISPIELE/SGB_II/)
```

### 7.2 Управление сроками (Fristenmanagement)

**Критически важно:** пропущенные процессуальные сроки часто невосполнимы.

**Правило трёх уровней напоминаний:**
```
Срок X
├── -14 дней: первое напоминание
├── -7 дней: второе напоминание
└── -2 дня: срочное напоминание
```

**Инструменты:** Nextcloud Tasks (selfhosted), Trello, простая таблица с условным форматированием в LibreOffice Calc

### 7.3 База знаний прецедентов

**Почему важно:**
Аналогичные дела часто повторяются. Задокументированный прецедент экономит часы работы.

**Структура (реализована в этой базе):**
```
04_FALLBEISPIELE/
├── SGB_II/
│   ├── 2026-02-27_KdU-Widerspruch-Angemessenheit.md
│   └── README.md
├── SGB_XII/
└── AsylbLG/
```

**Что документировать в каждом случае:**
- Фактическая ситуация (анонимизировано)
- Правовая квалификация
- Предпринятые шаги
- Результат
- Выводы для будущих дел

## 8. Универсальные инструменты

### 8.1 Системы управления знаниями

| Инструмент | Тип | Лучше всего для |
|-----------|-----|----------------|
| **Obsidian** | Локальный, Markdown | Личная база знаний, связи между заметками |
| **Zettlr** | Локальный, Markdown | Академическое письмо |
| **Notion** | Облако | Команды, гибкие базы данных |
| **Joplin** | Локальный/облако, open source | Конфиденциальные заметки |
| **Logseq** | Локальный, open source | Граф знаний, ежедневные заметки |
| **MediaWiki** | Selfhosted | Командные вики (как Wikipedia) |
| **DokuWiki** | Selfhosted | Проще чем MediaWiki, плоские файлы |

**Для этой базы знаний (Git + Markdown):**
Текущий подход — один из лучших для командного использования. Преимущества:
- Полная история изменений (Git)
- Работает в любом редакторе
- Не зависит от платного сервиса
- Поиск через `grep` / IDE

### 8.2 Управление документами (Document Management)

| Инструмент | Описание |
|-----------|---------|
| **Paperless-ngx** | Selfhosted DMS; OCR, теги, поиск в PDF |
| **Nextcloud** | Облачное хранилище + совместная работа |
| **Alfresco** | Корпоративный DMS (open source) |

**Paperless-ngx** особенно ценен: сканируй бумажные документы → автоматическое распознавание текста → полнотекстовый поиск.

### 8.3 Поиск и индексирование

| Инструмент | Применение |
|-----------|-----------|
| **grep / ripgrep** | Быстрый поиск по файлам (командная строка) |
| **fzf** | Интерактивный фильтр для командной строки |
| **Elasticsearch** | Масштабируемый полнотекстовый поиск |
| **Typesense** | Быстрый поиск, проще чем Elasticsearch |
| **MeiliSearch** | Open source, легко развернуть |

## 9. Стратегии поиска

### 9.1 Булевы операторы

**Базовые операторы:**

```
AND   — оба термина: Widerspruch AND Jobcenter
OR    — хотя бы один: SGB_II OR SGB_XII
NOT   — исключить: Wohnung NOT Eigenheim
"..."  — точная фраза: "angemessene Unterkunftskosten"
*      — маска: Beschäftig* (находит: Beschäftigung, beschäftigt...)
( )    — группировка: (SGB II OR SGB XII) AND Widerspruch
```

**В Google:**
```
site:sozialgerichtsbarkeit.de "§22 SGB II" "unangemessen"
filetype:pdf Bürgergeld Widerspruch Muster 2026
intitle:KdU Angemessenheit 2025..2026
```

### 9.2 Фасетный поиск (Faceted Search)

Фильтрация по нескольким измерениям одновременно:

```
Результаты 1247 документов
├── Тип: [Закон (234)] [Решение суда (589)] [Комментарий (424)]
├── Год: [2024 (312)] [2025 (567)] [2026 (368)]
├── Суд: [BSG (89)] [LSG (234)] [SG (266)]
└── Тема: [KdU (389)] [Sanktionen (201)] [Regelbedarf (657)]
```

### 9.3 Семантический поиск

**Традиционный поиск:** ищет точное совпадение слов
**Семантический поиск:** понимает смысл, находит синонимы и связанные концепции

**Пример:**
- Запрос: "обжалование отказа в пособии"
- Семантический поиск найдёт: Widerspruch, Klage, Rechtsbehelf, Beschwerde

**Инструменты:** новые версии поисковиков (Google, Bing), специализированные системы с vector embeddings

### 9.4 Стратегия "снежного кома" (Snowballing)

**Прямое снежное болото:** нашёл документ → посмотри все источники в нём
**Обратное снежное болото:** нашёл документ → кто на него ссылается?

**Для юридической базы:**
```
BSG B 14 AS 50/20 R
  ├── Ссылается на: BSG B 14 AS 65/18 R, BVerfG 1 BvL 7/16
  └── На него ссылаются: LSG NRW L 7 AS 1234/22, SG Köln S 31 AS 5678/23
```

## 10. Метаданные и теги

### 10.1 Почему метаданные важнее контента

> "Данные без метаданных — это как книги без обложек в тёмной комнате."

Метаданные позволяют:
- Фильтровать без полного чтения
- Отслеживать актуальность
- Автоматически строить индексы
- Понять контекст без чтения всего документа

### 10.2 Схема метаданных для этой базы (расширенная)

```yaml
---
# Обязательные поля
datum: 2026-02-27           # ISO 8601
typ: Gesetz | Urteil | Kommentar | Vorlage | Fallbeispiel | Aktuelles | Methodik
thema: SGB_II | SGB_XII | AsylbLG | SGB_VIII | SGB_XI | Wohnen | Allgemein
status: aktuell | veraltet | in-bearbeitung | archiviert

# Рекомендуемые поля
schlagworte: [KdU, Angemessenheit, Widerspruch]  # из контролируемого словаря
quelle: BSG B 14 AS 50/20 R | BGBl. I S. 1 | URL
autor: [Name]                   # автор записи в базе (не источника)
geprueft_am: 2026-02-27         # когда последний раз проверялась актуальность

# Опциональные поля
aktenzeichen: B 14 AS 50/20 R
gericht: BSG | LSG | SG | BVerfG
bundesland: NRW | Bayern | Berlin | ...
zielgruppe: [Klienten, Sachbearbeiter, Juristen]
schwierigkeitsgrad: Basis | Fortgeschritten | Experte
verwandte_dokumente:
  - ../Leistungen/KdU-Grundlagen.md
  - ../../04_FALLBEISPIELE/SGB_II/2026-02-27_KdU-Fall.md
---
```

### 10.3 Контролируемый словарь тегов (Controlled Vocabulary)

**Проблема:** без договорённости у каждого свои теги.
- Один пишет `KdU`, другой `Kosten_der_Unterkunft`, третий `Unterkunftskosten`

**Решение:** создать и придерживаться официального списка тегов.

Для этой базы рекомендуется создать файл `00_METHODIK/schlagworte-liste.md`:

```markdown
## Утверждённые теги (Schlagworte)

### Правовые области
- SGB-II, SGB-XII, SGB-VIII, SGB-XI, AsylbLG
- Grundgesetz, EMRK

### Тематические теги
- KdU (Kosten der Unterkunft — НИКОГДА не Unterkunftskosten)
- Regelbedarf
- Sanktionen
- Widerspruch
- Klage
- Buergergeld (НЕ Bürgergeld — для совместимости)
```

## 11. Безопасность и конфиденциальность

### 11.1 Уровни конфиденциальности данных

| Уровень | Примеры | Меры защиты |
|---------|---------|-------------|
| **Публичный** | Законы, судебные решения, общая информация | Стандартное хранение |
| **Внутренний** | Внутренние процедуры, методологии | Ограниченный доступ, пароли |
| **Конфиденциальный** | Данные клиентов (анонимизированные) | Шифрование, VPN |
| **Строго конфиденциальный** | Личные данные клиентов, свидетелей | Полное шифрование, air-gap |

### 11.2 Анонимизация данных

**Псевдонимизация** (заменить имя на ID):
```
Anita Müller, geb. 15.03.1985 → K-2026-042, geb. 1985
```

**Полная анонимизация** (невозможно восстановить):
```
K-2026-042, Frau, ca. 40 Jahre → удалить дату рождения
```

**DSGVO (GDPR):** в Германии действует строгое законодательство о защите данных. Данные клиентов — персональные данные, требующие законного основания для обработки.

### 11.3 Шифрование

**Файлы:** VeraCrypt (контейнеры), GPG (отдельные файлы)
**Диски:** BitLocker (Windows), FileVault (Mac), LUKS (Linux)
**Коммуникация:** Signal, ProtonMail
**Пароли:** KeePassXC (локально), Bitwarden (облако)

### 11.4 Резервное копирование (3-2-1 правило)

```
3 копии данных
2 разных носителя (SSD + внешний HDD)
1 копия за пределами офиса (облако или другое здание)
```

**Для чувствительных данных:** зашифрованное облако (Proton Drive, Nextcloud selfhosted)

## 12. ИИ и автоматизация

### 12.1 OCR (распознавание текста)

**Зачем:** сканированные PDF не доступны для поиска. OCR превращает изображения в текст.

| Инструмент | Описание |
|-----------|---------|
| **Tesseract** | Open source, поддерживает немецкий, командная строка |
| **OCRmyPDF** | Надстройка над Tesseract, добавляет текстовый слой в PDF |
| **Paperless-ngx** | Автоматический OCR при загрузке |
| **Adobe Acrobat** | Коммерческий, высокое качество |

```bash
# Пример: добавить OCR-слой к PDF (сохранить поиск)
ocrmypdf --language deu input.pdf output.pdf
```

### 12.2 Автоматическая классификация

**Что можно автоматизировать:**
- Определение типа документа (закон / решение суда / письмо)
- Извлечение дат, номеров дел, имён (Named Entity Recognition)
- Категоризация по теме
- Определение срочности (для сроков)

**Инструменты:** spaCy (Python, NER), Hugging Face (модели для немецкого языка), ChatGPT/Claude API (классификация по описанию)

### 12.3 Суммаризация

**Применение:** быстрое понимание длинных судебных решений.

**Важно:** ИИ может ошибаться в юридических вопросах. Автоматические резюме — только для первичной навигации, не для принятия решений.

**Рекомендуемый процесс:**
```
Длинный документ (50 стр.)
      ↓
Автоматическое резюме (ИИ)
      ↓
Быстрая проверка специалистом
      ↓
Добавление в базу с пометкой "ИИ-резюме"
```

### 12.4 Автоматическое обновление индексов

**В этой базе** уже есть `scripts/gen-index.sh`. Такой подход можно расширить:

```bash
# Автоматически:
# 1. Найти все .md файлы
# 2. Извлечь метаданные
# 3. Обновить INDEX.md
# 4. Проверить сломанные ссылки
# 5. Найти документы без метаданных
```

## 15. Практические советы и мнения

### 15.1 Главные ошибки при создании информационных систем

**Ошибка 1: Избыточная сложность**
Система из 50 категорий, которую никто не понимает — хуже простого `inbox/`.
→ **Начни просто. Усложняй только при реальной необходимости.**

**Ошибка 2: Перфекционизм как барьер**
"Я добавлю это, когда правильно оформлю." → документ теряется.
→ **Лучше неидеальная запись сейчас, чем идеальная никогда.**

**Ошибка 3: Система для одного**
База знаний, понятная только создателю — не база знаний.
→ **Пиши так, чтобы новый коллега разобрался без объяснений.**

**Ошибка 4: Отсутствие обслуживания**
Устаревшие ссылки, неактуальные законы — хуже пустоты, создают ложное чувство уверенности.
→ **Добавь дату проверки (`geprueft_am`) и регулярный ревизионный процесс.**

**Ошибка 5: Поиск "идеального инструмента"**
Смена инструментов каждые полгода — контрпродуктивна.
→ **Лучший инструмент — тот, который реально используется.**

### 15.2 Принципы, которые работают

**"Inbox Zero" для информации:**
Каждый входящий документ либо обрабатывается сразу (если <2 минут), либо добавляется в очередь.

**"Two minute rule":**
Если добавление занимает <2 минут — сделай сейчас.

**"Evergreen notes" (Энди Матущак):**
Заметки должны обновляться и оставаться актуальными, а не быть "снимками момента". Дата в имени файла — для хроники событий, не для постоянных концептуальных документов.

**Separation of concerns:**
- Файлы оригинальных документов — в одном месте (неизменны)
- Аналитические заметки — отдельно
- Задачи и дедлайны — в системе задач, не в документах

### 15.3 О ценности open source и открытых форматов

**Мнение:** использование проприетарных форматов (DOCX, Notion-экспорт, Evernote) — это риск.

- Компании закрываются, поднимают цены, меняют условия
- Твои данные могут стать заложниками платформы
- Open source + открытые форматы (Markdown, CSV, JSON) — долгосрочная инвестиция

**Эта база знаний** использует Git + Markdown — правильный выбор для долгосрочного хранения.

### 15.4 Рекомендации для разных масштабов

| Масштаб | Рекомендация |
|---------|-------------|
| **1 человек** | Obsidian (локально) + Git для резервной копии |
| **2-5 человек** | Git + Markdown (как эта база) ИЛИ DokuWiki |
| **5-20 человек** | Nextcloud + Paperless-ngx + эта база |
| **20+ человек** | Confluence/MediaWiki + специализированный DMS |

### 15.5 Об ИИ-инструментах в 2026

ИИ (LLM) полезны для:
- Суммаризации длинных текстов (проверяй важные пункты!)
- Первичной классификации документов
- Генерации черновиков шаблонов
- Поиска связей между концепциями

ИИ **ненадёжны** для:
- Точных юридических цитат (галлюцинации)
- Актуальных данных (знания могут быть устаревшими)
- Замены юридической экспертизы

**Правило:** ИИ — ассистент, не авторитет. Всегда верифицируй по первоисточникам.
